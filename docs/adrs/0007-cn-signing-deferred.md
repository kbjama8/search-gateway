# ADR-0007: Chinese-Ecosystem Signing Sources Stay Deferred (Douyin/XHS)

- Status: **accepted** (2026-08-23)
- Decision owner: KBJ (locked in D3, reaffirmed PHASE8 Plan 5)
- Related: `docs/extraction/PLAN.md` (D3), `docs/extraction/LESSONS.md` §3.5,
  §6 (R-items)

## Context

Two major Chinese platforms remain outside the registry (22 → 23 with
zhihu_hot; douyin/xiaohongshu still out) because both require
reverse-engineered request signing that drifts:

- **Douyin** — the x-gorgon suite (X-Gorgon, X-Argus, X-Khronos, X-Ladon,
  X-Helios, X-Medusa). Existing implementations use Unicorn CPU emulation +
  Android JNI environments exposed as HTTP services; difficulty rated very
  high; 2026 state unconfirmed (PHASE8 research §2.2).
- **Xiaohongshu (XHS)** — x-s/x-t/x-s-common on `edith.xiaohongshu.com`,
  generated by obfuscated JS (`window._webmsxyw`). The header generator
  **drifts periodically** (replayed headers fail 461/sign-error) and since
  ~March 2026 the data APIs reject the `XYS_` format with **HTTP 406**
  (verified 2026-08-23).

## Decision

Keep both deferred. No signing implementation is scheduled. The registry
grows to 23 with the anonymous zhihu hot-list (ADR context: R11) and stays
there until revival triggers fire.

## Consequences

- **Positive:** zero permanent maintenance burden from two hostile signing
  surfaces; the browser tier (OpenCLI/Camoufox) remains the honest fallback
  for these platforms when a research need actually exists.
- **Negative:** CN coverage misses the two biggest consumer platforms; a
  future need would require days of build + ongoing drift maintenance.

## Revival triggers (all three must hold)

1. **Proxy tier funded and live** (CN risk control correlates on IP
   reputation — direct-IP signing work gets throttled immediately);
2. A **verified 2026 signing implementation** exists for the target (not a
   stale fork) with a maintainable update cadence;
3. A **concrete research need** for the platform's content exists.
